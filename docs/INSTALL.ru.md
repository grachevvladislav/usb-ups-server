# Установка USB UPS Server на Synology DSM 7.2.2+

[На главную](../README.ru.md) · [English](INSTALL.md) · [Если не работает](TROUBLESHOOTING.ru.md)

## Что потребуется

- DSM 7.2.2 или выше, вход в DSM через HTTPS и учётная запись администратора.
- NAS с процессором x86_64 или aarch64. Архитектура выбирается по реальному
  процессору, а не по названию модели в загрузчике Xpenology.
- USB-кабель передачи данных от ИБП к NAS.
- Для первого назначения прав USB — собственный SSH-доступ с `sudo`.

Пакет находится в разработке. Чтение показаний и обнаружение сервера в DSM
проверены на первом x86_64 NAS. Автоматический безопасный останов ещё не проверен.
Не меняйте действующую защиту рабочего NAS во время нестабильного питания.

## Где взять пакет

Готовые SPK пока не опубликованы в GitHub Releases. Не ищите несуществующую
ссылку «Latest download»: разработчик может передать тестовую сборку либо
можно собрать её из исходников на компьютере с Go 1.23+ и Python 3:

```sh
git clone https://github.com/grachevvladislav/usb-ups-server.git
cd usb-ups-server
python3 dsm/tools/build.py --arch x86_64
python3 dsm/tools/check_spk.py dist/usb-ups-server-*-x86_64.spk
```

Для ARM64 замените `x86_64` на `aarch64` в обеих командах. Если в `dist/`
несколько версий, укажите точное имя проверяемого файла вместо `*`.
Сборщик скачивает зафиксированные компоненты NUT и проверяет их SHA-256.
На самом NAS Go, Python и Docker не нужны.

| Процессор NAS | Файл |
| --- | --- |
| Intel / AMD, 64 бита | `usb-ups-server-<версия>-x86_64.spk` |
| ARM, 64 бита | `usb-ups-server-<версия>-aarch64.spk` |

32-битные ARM-модели пока не поддерживаются. Наличие ARM64-сборки не означает,
что пакет уже испытан на каждой ARM-модели и версии DSM.

## Установка и обновление

1. В DSM откройте **Центр пакетов → Установка вручную**.
2. Выберите подходящий `.spk` и завершите установку. Проверьте имя пакета и источник,
   если DSM показывает предупреждение о стороннем разработчике.
3. Откройте **USB UPS Server** в главном меню DSM. Используется текущая сессия
   администратора.
4. После обновления закройте старое окно приложения и обновите страницу DSM.
   Затем откройте приложение снова.

Обновление кратковременно перезапускает собственную службу пакета и обновляет
конфигурацию nginx. Настройки сохраняются. Перезагрузка NAS для обновления SPK
не нужна. Установка пакета сама по себе не включает защиту NAS.

## Подключение ИБП

1. Подключите USB-кабель ИБП к NAS.
2. Откройте **Настройки → Обновить список** и выберите устройство.
3. Для RICHCOMM «UPS USB Mon V2.0» `0925:1234` используется профиль
   `nutdrv_qx / armac`. Для другого ИБП можно запустить **Подобрать драйвер**
   при выключенном мониторинге; подбор занимает до пяти минут.
4. Выдайте USB-доступ, как описано ниже.
5. В поле **Адрес сервера NUT** используйте **LAN-IP самого NAS**, порт `3493`.
   При первой настройке приложение подставляет адрес текущего подключения DSM,
   если он принадлежит сетевому интерфейсу NAS. Если адресов несколько и однозначно
   выбрать один нельзя, укажите его вручную. Сохранённый ранее адрес не заменяется.
   При занятом порте `3493` можно временно проверить чтение на `3494`, но штатному
   клиенту DSM потребуется `3493`.
6. Включите мониторинг и нажмите **Применить**. Проверка занимает до 30 секунд;
   при неудаче приложение пытается вернуть предыдущие настройки.
7. Откройте **Обзор**. `OL` означает питание от сети, `OB` — от батареи,
   `LB` — низкий заряд. Появятся только измерения, которые сообщает ваш ИБП.

Один USB-ИБП должен обслуживать один драйвер. Если этот же ИБП уже читает
штатная USB-служба DSM или другой NUT, сначала спланируйте переключение.
Не останавливайте все службы ИБП вслепую.

## Доступ к USB

Узнайте VID:PID в списке USB приложения. Пример ниже относится **только** к
проверенному устройству `0925:1234`; для другого устройства замените оба ID.

Если приложению не хватает USB-прав, оно показывает окно с командой для
выбранного устройства. Выполните её в собственной SSH-сессии на NAS:

```sh
sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh install-rule 0925 1234
```

Переподключите **USB-кабель**, затем обновите список. Правило выдаёт доступ
пользователю пакета только к совпадающему устройству. Не используйте `chmod 777`
для всего `/dev/bus/usb` и не запускайте приложение от root.

Если команда не поддерживается на вашей DSM, сначала [соберите диагностику](TROUBLESHOOTING.ru.md#что-приложить-к-сообщению).
Разовый вариант при наличии `setfacl`:

```sh
sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh grant 0925 1234
```

Такой доступ сбрасывается после переподключения. Постоянство udev-правила после
обновления DSM требует проверки. На Xpenology N40L отдельно требуется рабочий
OHCI-драйвер — [подробности](TROUBLESHOOTING.ru.md#xpenology-n40l-и-ohci).

## Подключение DSM к серверу NUT

**Не рассчитывайте на `127.0.0.1`: скорее всего, DSM не примет этот адрес.**
На проверенной DSM 7.2.2 поле сервера отвергает localhost. Даже если приложение
успешно читает ИБП через `127.0.0.1`, подключение штатного клиента DSM через
LAN-IP не заработает, пока NUT слушает только localhost. Используйте **один и
тот же LAN-IP NAS** в приложении и в настройках ИБП DSM.

Показания в приложении и защита NAS — два отдельных шага.

1. В приложении задайте **Адрес сервера NUT** равным LAN-IP NAS, порт `3493`,
   нажмите **Применить**. Для Docker указывайте IP Linux-хоста.
2. Откройте **Панель управления → Оборудование и питание → ИБП**.
3. Включите поддержку ИБП, выберите **Сервер ИБП Synology** и укажите IP сервера.
   Для приложения на том же NAS это его собственный LAN-IP.
4. Примените настройки и проверьте состояние подключения и информацию об устройстве.
5. Выберите процедуру перехода в безопасное состояние по требованиям своей системы.

DSM 7.2.2 на тестовом NAS отвергает `127.0.0.1` в этом поле, но принимает
собственный LAN-IP. В приложении адрес прослушивания должен совпадать с указанным
в DSM. Привязка к LAN-IP открывает NUT в локальной сети: разрешайте TCP 3493
только нужным клиентам. Пакет не открывает правила брандмауэра автоматически.

Для совместимости с DSM используются имя ИБП `ups`, пользователь `monuser`,
пароль `secret`. Вариант «включить сетевой сервер ИБП» в самой DSM — другая роль;
здесь DSM должна подключаться к серверу приложения.

На первом NAS DSM показала «Подключено» и модель «UPS». Испытание `OB`/`LB` и
безопасного останова ещё не проведено. Проводите его отдельно на тестовой системе
с резервной копией и планом восстановления, прежде чем полагаться на эту защиту.

## Проверка после настройки

- В **Обзоре** время показаний обновляется, драйвер и NUT работают.
- DSM показывает подключённый ИБП.
- После переподключения USB показания восстанавливаются.
- После контролируемого отключения **входного питания ИБП** состояние меняется
  `OL → OB`, после возврата питания — `OL`. Не отключайте выходы ИБП на рабочий NAS.
- Полный сценарий безопасного останова проверяется отдельно; не разряжайте
  батарею до `LB` на рабочем NAS ради первичной диагностики.

## Удаление и восстановление

Перед удалением пакета перенастройте клиентов, которые используют его NUT-сервер.
Если устанавливали USB-правило, удалите его до удаления пакета:

```sh
sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh remove-rule 0925 1234
```

Затем переподключите USB. Пакет удаляется через Центр пакетов. Не удаляйте
системные NUT-файлы DSM. Хранение настроек и резервные файлы описаны
в [технической инструкции](DSM.ru.md#хранение-и-восстановление).
