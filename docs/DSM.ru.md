# USB UPS Server для DSM 7.2.2+

Версия 0.1.10 — пакет для ручной установки и аппаратной проверки. Он запускает
собственный NUT от пользователя `usb-ups-server`, показывает состояние USB‑ИБП,
подбирает драйверы и публикует NUT для сетевых клиентов. Docker и Python на NAS
не требуются. Нативный интерфейс проверяет текущую сессию администратора DSM.
Вход через сессию DSM проверен на первом NAS.

**Передача показаний проверена на симуляторе и исходном USB-ИБП на первом NAS.
Защита самого NAS пока не проверена
на DSM. Наличие показаний в приложении не означает, что DSM уже настроен на
безопасное завершение работы.** Приложение не запускает `upsmon`, не выполняет
команды выключения и не переписывает системные конфиги Synology.

## Целевые устройства

| Сборка | Устройство для проверки | Состояние |
| --- | --- | --- |
| x86_64, GOAMD64=v1 | Xpenology DS3622xs+, AMD Turion II Neo N40L, DSM 7.2.2-72806 Update 10 | SPK установлен; RICHCOMM 0925:1234 читает OL, напряжения, нагрузку и температуру после загрузки OHCI и выдачи USB-доступа |
| aarch64 | DS423, DSM 7.4.1-90080 по данным пользователя | Следующий этап проверки |

Минимум в метаданных — DSM 7.2.2-72803. Верхней границы нет; это разрешает
установку на следующих версиях, но не заменяет проверку совместимости.
32-битные ARM-платформы пока не собираются. Базовый x86-64 выбран специально
для старого процессора N40L; требования оригинального DS3622xs+ не используются.

## Нативное приложение DSM (0.1.10)

DSM загружает `USBUPSServer.js` как `type: app`. Компоненты `v-app-instance` и
`v-app-window` создают штатное окно, а `v-form`, `v-form-item`, `v-input`,
`v-single-select`, `v-checkbox` и `v-button` — формы и элементы управления.
Используются Vue и оформление, предоставляемые DSM.

Разделы: «Обзор», «Настройки», «Журнал». Боковая навигация с иконками,
светлым выделением строки и синими заголовками оформлена по образцу Synology Drive. Значения NUT отображаются без
выдуманных показателей заряда/времени; все переменные доступны отдельно. Изменения
настроек применяются штатной кнопкой «Применить» с существующей проверкой и откатом.

API доступен на том же HTTPS-origin по `/webman/3rdparty/usb-ups-server/app/api/`.
Пакет регистрирует location через штатный `web-config` worker DSM 7.2+, без ручной
правки системных конфигов. Nginx пересылает запросы на `127.0.0.1:8788` и задаёт
достоверные IP клиента/сервера и HTTPS-протокол. Этот listener не доступен по сети.

Для каждого сеанса backend вызывает официальный `authenticate.cgi`, передавая
cookie текущего DSM-сеанса, SynoToken и CGI-окружение, затем проверяет группу `administrators`.
SynoToken берётся из same-origin `login.cgi` текущего сеанса и хранится только
в памяти окна. Успешный результат кешируется максимум 5 секунд; cookie не записываются в журнал
или диагностику. Процесс пакета продолжает работать от пользователя пакета.
Отсутствие/ошибка CGI, неподтверждённая сессия или отсутствие прав администратора
закрывают доступ. Имя пользователя из браузера, заголовок Authorization и прежний
ключ пакета не заменяют эту проверку. Изменения дополнительно проверяются по Origin
и пользовательскому заголовку. Отдельная сессия/пароль приложения в DSM не создаётся.

Прежний HTTPS-интерфейс на 8787 остаётся запасным каналом с прежним ключом; сессия
DSM не используется на этом внешнем интерфейсе. Оба канала запрещают встраивание.

При обновлении DSM применяет конфигурацию пакета и обновляет nginx. Возможен
кратковременный разрыв соединения браузера; перезагрузка NAS не нужна. Закройте
старое окно и обновите страницу DSM, чтобы загрузился новый JavaScript.

## Первый тест: установка и открытие

1. Скопировать `dist/usb-ups-server-0.1.10-x86_64.spk` на компьютер с браузером DSM.
2. «Центр пакетов → Ручная установка», выбрать файл и запустить пакет.
3. Открыть **USB UPS Server** из меню DSM: интерфейс открывается окном внутри
   рабочего стола DSM. Для этого входите в DSM по HTTPS. Запасной адрес:
   `https://IP-NAS:8787/`. Для сертификата приложения браузер покажет предупреждение;
   проверьте адрес NAS перед переходом. Можно позднее заменить `server.crt` и
   `server.key` собственным сертификатом в каталоге данных пакета.
4. Для запасного интерфейса 8787 получить ключ через собственную SSH-сессию:

   ```sh
   sudo cat /var/packages/usb-ups-server/var/admin-token
   ```

5. В DSM отдельный ключ не нужен: используется текущая сессия администратора.
   Команда выше нужна только для запасного интерфейса на порту 8787. На первом
   запуске мониторинг выключен.

Если пакет не устанавливается, прислать полный текст ошибки Центра пакетов.
Если не запускается или не открывается:

```sh
sudo cat /var/packages/usb-ups-server/var/service.log
```

Порт 8787/TCP нужен для HTTPS. NUT использует отдельный порт 3493/TCP и по
умолчанию слушает только `127.0.0.1`. Пакет не создаёт разрешающие правила DSM
firewall автоматически. Не отключайте весь firewall для диагностики.

## Второй тест: подключение исходного ИБП

Исходный проект проверял RICHCOMM «UPS USB Mon V2.0», USB `0925:1234`:

```text
driver: nutdrv_qx
subdriver: armac
vendor_id: 0925
product_id: 1234
```

1. Подключить USB‑кабель к NAS. В приложении открыть «Настройки → Обновить список».
2. Выбрать устройство `0925:1234`. Интерфейс подставит `nutdrv_qx / armac`.
   Если список пуст, собрать диагностику командой ниже. Для известного ИБП
   перебор драйверов не нужен.
3. Убедиться, что штатная служба DSM не использует этот ИБП как USB UPS.
   Пакет сам её не останавливает. При переключении уже настроенной защиты NAS
   возникает период без мониторинга — проводить проверку при стабильном питании.
4. Выдать пользователю пакета доступ **только к этому USB‑устройству**:

   ```sh
   sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh grant 0925 1234
   ```

   Это изменяет ACL текущего узла `/dev/bus/usb/BBB/DDD`. Доступ сбрасывается
   после переподключения или перезагрузки; до настройки постоянного правила
   команду потребуется повторять. Если `setfacl` отсутствует, не меняйте права
   всех USB-устройств: сначала пришлите результат сбора диагностики.
5. Использовать LAN-IP NAS; при первой настройке приложение автоматически
   подставляет локальный IPv4 текущего подключения DSM, если он определён.
   Сохранённые настройки не меняются. `127.0.0.1`, скорее всего, не будет принят
   штатным клиентом DSM. Если порт 3493 занят, для чтения можно временно указать
   **3494**, но клиенту DSM нужен именно 3493.
6. Включить мониторинг и нажать «Применить». Проверка занимает до
   30 секунд. При ошибке старые настройки и служба восстанавливаются;
   неудача восстановления явно отображается в состоянии.
7. На экране «Обзор» должны появиться `OL`, напряжение, нагрузка и другие
   реально поддерживаемые измерения. Отсутствующие заряд и время не вычисляются.
8. Скачать «Журнал → Скачать диагностику» и прислать результат. Там есть
   USB‑идентификаторы, серийный номер и вывод драйвера, но нет ключа входа.

Только после успешного чтения можно кратковременно отключить **входное сетевое
питание ИБП**, оставив его выходы включёнными. Ожидается `OL → OB → OL`.
До отдельной проверки защиты DSM не доводить батарею до `LB` на рабочем NAS.

## Постоянный доступ к USB

### Если ИБП отсутствует в списке USB на Xpenology N40L

На первом тестовом NAS обнаружены AMD OHCI-контроллеры `1002:4397` без
привязанного драйвера. В конфигурации SDK broadwellnk OHCI отключён, а в
проверенном архиве Arc Modules 26.09.06 отсутствуют `ohci-hcd.ko` и `ohci-pci.ko`.
Изменение драйвера NUT или прав USB не добавляет отсутствующий драйвер контроллера.
Для этой конкретной платформы подготовлен отдельный временный тест:
[OHCI broadwellnk / DSM 7.2](../dsm/kernel/ohci/README.ru.md).
Модули не включены в обычный SPK и автоматически не загружаются.

### Правило udev

После успешного разового чтения и проверки наличия активного udev:

```sh
sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh install-rule 0925 1234
```

Команда создаёт `/etc/udev/rules.d/99-usb-ups-server-0925-1234.rules`:
только совпадающее USB‑устройство получает группу пакета и режим 0660. Она не
создаёт root-службу и не запускает код пакета из root-задачи при загрузке.
Если DSM не предоставляет стандартный udev, команда завершится с объяснением;
для этой системы механизм выберем после диагностики.

После установки правила переподключить USB и проверить восстановление показаний.
На первом N40L OHCI пока загружен временно: проверку перезагрузки отложить до
настройки загрузки модулей через Arc. Затем проверить права и показания после
перезагрузки. Сохранность правила после обновления DSM требует проверки.
Удаление правила перед удалением пакета:

```sh
sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh remove-rule 0925 1234
sudo sh /var/packages/usb-ups-server/target/tools/usb-access.sh revoke 0925 1234
```

После удаления правила переподключить USB для восстановления штатных прав.

## Проверка защиты этого же NAS — отдельный этап

Предпочтительная схема: наш драйвер читает USB, наш `upsd` публикует `ups`, штатный
клиент DSM выполняет свою процедуру перехода в безопасное состояние.
На первом NAS с DSM 7.2.2-72806 Update 10 подключение к собственному серверу
подтверждено через собственный LAN-IP NAS, порт `3493`;
в DSM включена поддержка ИБП, выбран «Сервер ИБП Synology», указан тот же IP.
DSM применил настройки и показал «Подключено», производителя «Generic USB to
Serial», модель «UPS». Заряд не поддерживается, расчётное время недоступно.
Это подтверждает обнаружение сервера; работу системного монитора при `OB`/`LB`
и безопасный останов NAS ещё предстоит проверить.

После успешного второго теста проверить:

1. Выбор «Сервер Synology UPS» и собственного LAN-IP NAS. Наш сервер должен
   слушать этот адрес или `0.0.0.0`. Не рассчитывать на `127.0.0.1`.
2. Отсутствие конфликта системного `upsd` и нашего сервера на 3493.
3. После применения настроек DSM не захватывает USB своим драйвером повторно.
4. DSM отображает информацию об ИБП и видит переход `OL → OB`.
5. На тестовом NAS: заданная задержка DSM, переход в безопасное состояние,
   порядок остановки пакета, поведение при восстановлении питания.

На DSM 7.2.2-72806 Update 10 интерфейс отвергает `127.0.0.1` с сообщением
«Указан неверный IP-адрес». LAN-IP этого же NAS принимается. Если используется
LAN-IP, адрес `listen` в приложении должен совпадать с ним: сервер, слушающий
только `127.0.0.1`, недоступен через LAN-IP. При таком переключении NUT становится
доступен через сетевой интерфейс; область доступа нужно учитывать в правилах
межсетевого экрана. На момент проверки брандмауэр первого NAS был выключен;
пользователь отдельно разрешил публикацию NUT через LAN-IP.

Если DSM отвергнет локальный сервер или изменит службы так, что возникнет конфликт,
сначала зафиксировать процессы и порты. Не подменять `/usr/syno`, системный NUT
и не добавлять root-команды выключения в обход штатной процедуры.

## Сбор диагностики DSM

Команда выполняет только чтение, не выводит ключ входа и содержимое конфигурации:

```sh
sh /var/packages/usb-ups-server/target/tools/collect-dsm.sh
```

При отсутствии доступа к приложению полезны также:

```sh
sudo tail -n 100 /var/packages/usb-ups-server/var/service.log
sudo tail -n 100 /var/packages/usb-ups-server/var/nut.log
```

## Хранение и восстановление

Данные находятся в `/var/packages/usb-ups-server/var` с правами 0700:

- `settings.json` — последняя успешно применённая конфигурация;
- `admin-token` — ключ администратора, файл 0600;
- `server.crt`, `server.key` — сертификат и закрытый ключ;
- `conf/`, `run/` — только конфиги и сокеты собственного NUT;
- `nut.log`, `nut.log.1` — журнал NUT, до 1 МиБ каждый;
- `service.log` — ошибки запуска службы;
- `daemon.pid` — PID с проверкой принадлежности исполняемому файлу.

При обновлении `target` заменяется, а `var` сохраняется. Обновление и удаление
нужно проверить в DSM. Пакет не удаляет административные udev‑правила автоматически.
Перед удалением пакета перенастроить клиентов, зависящих от его NUT.

Watchdog проверяет данные каждые 15 секунд; после трёх ошибок перезапускает
собственные процессы. Лимит — три попытки без подтверждённого восстановления.
После исчерпания лимита приложение остаётся доступным с ошибкой; для новой
попытки сохранить настройки повторно. Оно не перезапускает штатные службы DSM.

## API

Все `/api/*`, кроме входа, требуют сессионную cookie или
`Authorization: Bearer <ключ>`. POST также требует `X-UPS-Request: 1` и JSON.
Доступны `/api/status`, `/api/settings`, `/api/usb`, `/api/logs`,
`/api/diagnostics`, `/api/metrics`; POST `/api/detect` возвращает найденный профиль
без включения мониторинга. Подбор не меняет рабочую конфигурацию.
Метрики Prometheus также защищены ключом. HTTPS обязателен вне loopback.

## Сборка и проверки

На машине разработчика нужны Go 1.23+ и Python 3.12+. На NAS они не нужны.

```sh
cd dsm
go test -race ./...
go vet ./...
cd ..
python3 -m unittest discover -s dsm/tools -p 'test_*.py'
shellcheck dsm/packaging/scripts/* dsm/tools/host/*.sh
python3 dsm/tools/build.py --arch x86_64
python3 dsm/tools/build.py --arch aarch64
python3 dsm/tools/check_spk.py dist/usb-ups-server-0.1.10-x86_64.spk
```

NUT 2.8.2 и библиотеки взяты из официального Alpine 3.22. Архивы и SHA256
зафиксированы в `dsm/tools/runtime-*.lock.json`. Сборка проверяет хеш каждого
архива; обновление lock выполняется явно командой `runtime.py lock --arch …`.
Библиотеки и musl loader находятся внутри пакета; `/lib` и libc DSM не меняются.
Init-скрипты и конфиги Alpine в NAS не устанавливаются.

CI проверяет Go, shell, упаковку и обе архитектуры. Отдельный тест запускает
комплектные `dummy-ups` и `upsd` под `nobody` в Debian, проверяет NUT → API
и потерю связи после остановки драйвера. Это проверка Linux-runtime, не DSM.

Локальный интерфейс без ИБП:

```sh
cd dsm
go run ./cmd/upsdsm --http --listen 127.0.0.1:18787 --data /tmp/usb-ups-dsm-dev
```

Открыть `http://127.0.0.1:18787`, ключ — в `/tmp/usb-ups-dsm-dev/admin-token`.
