# USB UPS Server — USB-ИБП для Synology DSM и Docker

**Русский** · [English](README.md) · [Установка в DSM](docs/INSTALL.ru.md) · [Диагностика](docs/TROUBLESHOOTING.ru.md)

Synology не видит ИБП по USB или не поддерживает его драйвер? USB UPS Server
читает состояние ИБП через **Network UPS Tools (NUT)** и предоставляет его
штатному клиенту DSM, TrueNAS или другому NUT-клиенту.

Можно установить приложение `.spk` прямо на NAS или подключить ИБП к отдельному
Linux-компьютеру и запустить сервер в Docker. Проверенный ИБП — **RICHCOMM
«UPS USB Mon V2.0», USB `0925:1234`**, драйвер `nutdrv_qx`, субдрайвер `armac`.
Совпадение производителя или USB ID не гарантирует поддержку всех ревизий ИБП.

## Какой вариант выбрать

| | Приложение DSM | Docker-сервер |
| --- | --- | --- |
| Куда подключён USB ИБП | В NAS | В отдельный Linux-хост |
| Интерфейс | Окно рабочего стола DSM, вход через текущую сессию администратора | Необязательная страница показаний |
| Требования | DSM 7.2.2+, x86_64 или aarch64 | Linux, Docker Compose и доступ к USB |
| Инструкция | [Установка SPK](docs/INSTALL.ru.md) | [Установка Docker](docs/DOCKER.ru.md) |

Приложение DSM включает NUT 2.8.2, выбор USB-устройства и драйвера, показания
напряжения, нагрузки и батареи, восстановление драйвера при сбое, журнал и
выгрузку диагностики. Docker и Python на NAS не нужны. Интерфейс работает в
окне DSM, без iframe и отдельного пароля приложения.

**Текущее состояние:** чтение USB-ИБП и обнаружение NUT-сервера в DSM проверены
на Xpenology DS3622xs+ / AMD N40L с DSM 7.2.2-72806 Update 10. Переход DSM в
безопасное состояние и завершение работы при пропадании питания **ещё не
проверены**. Наличие показаний само по себе не подтверждает защиту NAS.
ARM64-пакет собирается; проверка на DS423 запланирована.

## Быстрая установка в DSM

1. Получите или [соберите SPK](docs/INSTALL.ru.md#где-взять-пакет) для процессора
   своего NAS. Готовые пакеты в GitHub Releases пока не опубликованы.
2. Откройте **Центр пакетов → Установка вручную**, выберите `.spk` и запустите пакет.
3. Откройте **USB UPS Server** из главного меню DSM через HTTPS.
4. В **Настройках** обновите список USB и выберите ИБП. Для проверенного
   `0925:1234` приложение подставит `nutdrv_qx / armac`.
5. [Выдайте доступ к этому USB-устройству](docs/INSTALL.ru.md#доступ-к-usb),
   включите мониторинг и нажмите **Применить**. В **Обзоре** появятся показания.
6. Для защиты NAS отдельно [настройте штатный клиент DSM](docs/INSTALL.ru.md#подключение-dsm-к-серверу-nut).

## Если не работает

| Что произошло | Что проверить |
| --- | --- |
| ИБП нет в списке USB | [Кабель, контроллер и драйвер ядра](docs/TROUBLESHOOTING.ru.md#ибп-нет-в-списке-usb) |
| `Permission denied`, работает только от root | [Права на USB](docs/TROUBLESHOOTING.ru.md#нет-доступа-к-usb) |
| RICHCOMM `0925:1234`: `Entity not found` | [Драйвер и профиль Armac](docs/TROUBLESHOOTING.ru.md#richcomm-09251234-entity-not-found) |
| В приложении показания есть, DSM ИБП не видит | [Адрес NUT и настройки DSM](docs/TROUBLESHOOTING.ru.md#dsm-не-подключается-к-серверу-ибп) |
| Нет процента заряда и времени работы | [Какие показания поддерживает ИБП](docs/TROUBLESHOOTING.ru.md#нет-заряда-батареи-или-времени-работы) |
| Пустое окно или ошибка сессии после обновления | [Окно приложения](docs/TROUBLESHOOTING.ru.md#пустое-окно-или-ошибка-сессии-dsm) |
| N40L / Arc: без OHCI ИБП не определяется | [Особенности Xpenology](docs/TROUBLESHOOTING.ru.md#xpenology-n40l-и-ohci) |
