# Временный тест OHCI на Xpenology N40L

Цель: DS3622xs+ (`synology_broadwellnk_3622xs+`), DSM 7.2.2-72806 Update 10,
ядро `4.4.302+`, vermagic `4.4.302+ SMP mod_unload`.

На тестовом N40L PCI-контроллеры AMD `1002:4397` присутствуют без драйвера;
EHCI работает, а в установленном комплекте отсутствуют OHCI-модули.
Эти два драйвера добавляют поддержку контроллера USB 1.1, до которой
пользовательский драйвер NUT самостоятельно добраться не может.

Аппаратный тест 18 октября 2026 года: пользователь успешно загрузил оба модуля
через `test-load.sh`. ИБП `0925:1234` появился на USB-шине; после выдачи доступа
пакету `nutdrv_qx / armac` читает статус `OL`, напряжения, нагрузку и температуру.
После установки правила udev и повторного подключения USB свежие показания
восстановились. Постоянная загрузка модулей через Arc и проверка после
перезагрузки ещё не выполнены.

## Что проверено до запуска на NAS

- Исходники OHCI, заголовки ядра и компилятор взяты из официального архива Synology.
- Используются исходная конфигурация и Module.symvers платформы broadwellnk.
- ELF x86-64 и vermagic проверяются автоматически.
- Все обязательные импорты модулей проверяются по экспортам SDK и пары OHCI.
- Исходники, журнал, SHA256 и рецепты сборки включены в архив.

**Совпадение этих проверок не заменяет аппаратный тест. Загружаемый модуль ядра
при ошибке может вызвать зависание или перезагрузку NAS. Первый запуск проводить
в подходящее для прерывания работы время, с доступом к консоли.**

## Ручной тест

1. Скопировать архив `ohci-broadwellnk-7.2-4.4.302.tar.gz` в выбранный каталог NAS.
2. В собственной SSH-сессии перейти в этот каталог и распаковать:

   ```sh
   tar -xzf ohci-broadwellnk-7.2-4.4.302.tar.gz
   cd ohci-broadwellnk-7.2-4.4.302
   sudo sh test-load.sh
   ```

3. Скрипт проверяет SHA256, платформу, ядро и точное совпадение vermagic с
   установленным `ehci-pci.ko`. При несовпадении загрузки не будет.
4. После успешной загрузки переподключить USB ИБП и проверить:

   ```sh
   lspci -nnk | grep -A 3 -i 'USB controller'
   sudo dmesg | tail -n 60
   ```

5. Ожидается `Kernel driver in use: ohci-pci` у контроллеров `1002:4397`,
   новые USB-шины и появление ИБП `0925:1234` в приложении.
6. Передать результат проверки. После обнаружения ИБП отдельно настроить права
   USB и драйвер NUT. Сам факт загрузки OHCI ещё не означает защиты NAS.

Скрипт не меняет `/lib/modules`, ядро, ramdisk и автозагрузку Arc. Перезагрузка
удалит временно загруженные модули. Для ручного отката после остановки мониторинга:

```sh
sudo rmmod ohci_pci
sudo rmmod ohci_hcd
```

Не выгружать EHCI/usbcore. Постоянное добавление в Arc — только после успешного
аппаратного теста. В меню Arc Modules можно выбрать лишь существующие файлы;
в проверенном архиве arc-modules 26.09.06 для broadwellnk 7.2 этих OHCI-файлов нет.

## Повторная сборка

На машине разработчика с Docker и Python:

```sh
python3 dsm/kernel/ohci/build.py
```

Docker работает без privileged, доступа к USB, сети во время компиляции и
возможности загрузки модулей в ядро хоста. Результат — в `dist/`.
GCC-совместимый параметр в Makefile SDK заменяется с
`--param=allow-store-data-races=0` на `--allow-store-data-races`, как в инструментах Arc.
Сами исходники OHCI и сгенерированные заголовки конфигурации не изменяются.
